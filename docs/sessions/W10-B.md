## Summary

- `apps/watcher` is a Worker in its own wrangler project (local, staging, production) for a second
  Cloudflare account. It shares nothing with the backend: one D1 of its own, no KV, R2, service
  binding, Durable Object or queue, and no shared code beyond `@flocked/{verify,settle,tlock,abi}`
  (`test/isolation.test.ts` holds that line, down to the import graph of `src/**`). It reads the
  game only over public routes on `API_BASE_URL` and the chain over its own `BASE_RPC_URL`.
- Every minute it snapshots each locked round's published config **write-once**, so a later edit to
  what the API publishes cannot change what `RoundCreated` is compared with. A snapshot first taken
  at or after close makes the verdict `unable`, never `match`.
- Checks: `RoundCreated` field by field against that snapshot, plus the backend-independent rules
  (house creator = treasury, else the published payout wallet holding unrevoked Coinbase Verified
  Account and an allowed Verified Country; the launch defaults unless a matching override was
  published before lock; `beaconRound` the first drand round at or after `closesAt + beaconDelay`,
  inside the contract window); each `OutcomeProposed` by full recompute through `@flocked/verify`;
  and the routes into Refunded no proposal explains (void, `refundTooFew`, timeout).
- Verdicts are the pinned shape, EIP-191 by `WATCHER_KEY`, stored write-once and served at
  `GET /verdicts/:subject/:id`. A mismatch, an `unable`, or a proposal still without a verdict 30
  minutes on queues a page that survives an unreachable webhook (D1-backed, retried each tick).
- An `unable` is held back and retried until its deadline (15 min before close for `RoundCreated`,
  30 min after a proposal), so a slow RPC never freezes a round at `unable` while the guardian
  still has time to `voidRound`.

## Deviations

- **`packages/verify/src/bundle.ts` is edited** although the prompt puts `packages/**` out of scope:
  `new TextDecoder('utf-8', { fatal: true })` → `{ fatal: true, ignoreBOM: false }`.
  `@cloudflare/workers-types` types both options as required, so **as written the library does not
  typecheck inside any Worker that imports it** and the watcher could not be built. The change is
  behaviour-identical (`ignoreBOM` defaults to false everywhere) and no other wave-10 session
  touches the file.
- **PIPE-5's "anvil round with a wrong proposal" is not in this package.** The CI `check` job has no
  Foundry, so an anvil-backed test there would fail CI, and `e2e/**` is out of scope. The in-package
  half uses tampered fixtures and a fake chain reader over the real ABI shapes; the anvil half is
  specified for D below. Nothing is skipped or weakened to achieve it.
- **The pinned verdict needed subject names.** `src/verdict.ts` defines `stakes_round`,
  `stakes_proposal` and `stakes_refund`, reserving `free_anchor` / `free_settlement` for W11-B; the
  subject carries the mode so (subject, roundId) stays unique, and the body still carries `mode`.
  There is **one verdict per (subject, round)**, because a verdict is write-once evidence: a round
  re-proposed after a veto keeps its first `stakes_proposal` verdict, and the new proposal, having
  no verdict checked at or after it, pages through the 30-minute missing-verdict rule.
- **`unable` covers every check the watcher cannot run**, including an unconfigured `COUNTRY_ALLOW`
  and a failed attestation read. It is never a silent pass, and it pages.
- Within size M, no subagents. No test was skipped, deleted or weakened.
- This handoff is about 185 lines, over the template's ~120 (plan.md 3.2): five spec issues and the
  stack-test recipe D needs did not compress further without losing what the next session must do.

## Spec issues

1. **"Sealed picks" › Round config check, with "API":** the spec has the watcher snapshot the
   published config *at lock*, but no public route shows a round between lock (`opensAt − 6 h`) and
   open — `/rounds/today` returns only `opensAt ≤ now < closesAt`, `/rounds` lists closed rounds.
   The earliest independent snapshot is therefore at **open** (still hours before close), and the
   watcher records when it took it. Recommend naming open as the snapshot point, or adding
   `nextRoundId` to `/rounds/today` (it already returns `previousRoundId`) so lock is reachable.
2. **"Sealed picks" › Round config check vs. `apps/api/src/read/rounds.ts:227`:** `configWire`
   always publishes `overrides: []`, though the spec says each non-default value is published with
   its audit-log ID. Until the API fills it, **any** non-default Stakes value is a watcher mismatch
   that pages — which is the rule as written, but it would page on every seam-made round today.
   Recommend building the override list where admin config edits live (W11-A), or stating that the
   launch defaults are mandatory.
3. **"Smart contract" › Challenge window vs. "Profiles, leaderboards and rooms" › Rooms:** a room
   round is not publicly readable (`/rounds/:id` is members-only for rooms; `/rounds` lists daily
   rounds), so the watcher cannot verify a Stakes room round at all. Rooms-Stakes is off by default,
   so nothing is unwatched today. Recommend saying either that room rounds publish config and
   bundles publicly, or that they are outside the watcher's scope until they do.
4. **"Smart contract" › Challenge window ("allowed Verified Country attestations"):**
   `geo.stakes.allow` is backend config the watcher must not read, so it needs its own list, built
   here as the `COUNTRY_ALLOW` var (country codes; `geo.stakes.allow` also holds `US-NJ`-style
   entries, which the watcher matches at country level as `countryAllowed` does). Recommend the
   spec name where the watcher's list comes from and who keeps the two in step.
5. **Same section, the dead-man's switch:** the watcher also implements the 30-minute
   missing-verdict rule, so a tick that fails for one round still pages. Deliberate duplication,
   not a replacement for OA-19; recommend the spec say both exist.

## Open issues

- **Free is not watched yet** (W11-B): the Free lock, commitment and manifest anchor, Free
  settlement and refund, and the drand monitoring a rule-8 refund needs to be a match.
  `src/verdict.ts` reserves the subjects; `apps/watcher/migrations/0002` is W11-B's (W9-Z).
- **The recompute is one Worker invocation.** `@flocked/verify` decrypts sequentially (~6 ms an
  entry, W9-B), so a large Stakes round would pass the Worker CPU limit — fine at launch scale,
  wrong at 100k entries. W11-B or W13-B should split it (a Durable Object or a queue) or verify a
  sample plus the roots.
- **Bundle size** 2,277 KiB (424 KiB gzip), mostly BLS and tlock-js: fine on Workers Paid (OA-04),
  over the free plan's 3 MB uncompressed limit only if the second account is not paid.
- **`attestationTarget` resolves to no RPC** when `ATTESTATION_RPC_URL` is unset and the game chain
  is not the attestation network (staging): every author-round check is then `unable`, which pages.
- **No stack or e2e coverage yet** (`e2e/**` is out of scope): see below. The verdict route is
  public, unauthenticated and `no-store`; verdicts never change, so it could be cached later.
