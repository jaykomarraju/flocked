## Summary

- **H1 (the tick):** `driveCancellations` runs before any per-round work (and once more at the end only if step 4 abandoned a `createRound`, so it is still replaced in the same tick); the daily rounds are locked and visited first; a tick locks at most `ROOM_LOCKS_PER_TICK` (50) room rounds and visits a page of `ROOM_ROUNDS_PER_TICK` (50) live room rounds that rotates every minute. Open room rounds are skipped unless their Free lock leaf is pending or they are past close (a stalled alarm). With 300 rooms a tick costs at most 423 D1 statements (was over 1,000).
- **H1 (the cap):** at most `ROOM_MAX_OWNED` (10) open rooms per owner; `POST /rooms` answers 409 `conflict` past it, read inside the insert, so concurrent creates hold it.
- **M1, L1:** the lock's `UPDATE` and the quiet room-round close apply only while `rounds.question_id` is still the value read (`IS ?`) and the picked question still has the status read; a stale attempt re-reads the round and retries (3 attempts, then it throws and the next tick retries). The no-round-day close also requires the `question_id` read. Assign requires a `scheduled` round (read and batch guard). A room question's "lock still ahead" check uses the clock after moderation.
- **M2:** `limitUser('writes')` on `POST /rooms/:id/questions`; `refuseOverQuota` is exported from `questions/submit.ts` and the copy is gone. **M3:** the visit grant only for an active session user (as the daily grant). **L2:** `editQuestion` refuses room questions (`conflict`, the existing `refuseRoomQuestion`).
- **L3:** the room and member inserts require `users.status = 'active'` in SQL; a refused room insert fails the owner row's NOT NULL (its user ID comes from the inserted room), rolling the batch back. Both answer 403 `account_suspended`.
- **Decisions:** the 50-member cap counts only non-deleted members; the hand-over prefers the oldest active member, else the oldest non-deleted one (L4).
- **L5:** a Stakes stats call (the Stakes final's hook, inside an IndexerDO poll) applies at most `STATS_SIZES.stakesBatches` (8) batches, about 50 D1 statements; the rest waits for the next call. The scheduler tick gains step 6, `drainStakesStats`, one bounded Stakes call a minute, so a backlog always drains. Free calls are unchanged (7 days, unbounded batches).
- **L6:** split quality counts settled modes only (`m.status = 'settled'`), on the Creators board and on profiles; a refunded or voided mode has none.
- **`/prepare`:** for a room round, after the visibility check (a non-member still gets the 404), `rooms.stakes.enabled` (and `mode.stakes.enabled`, through `roomStakesEnabled`) must be on, else 403 `stakes_disabled` ("Stakes in rooms is paused").
- **`GET /rounds/:id`:** past beacon time a closed round's `pending` mode reads `revealing`, the WebSocket's `asOfClock` rule, in `readRound` (so the room detail's `currentRound` too).

## Deviations

- `test/scheduler/tx.test.ts` (T4 and W5-F1 C4): both found their `createRound` as `fake.sent[0]`. The tick's first sweep now replaces an earlier test's leftover pending transaction (same D1 per file) before this test's `createRound`, so they find it as the first non-`0x` transaction. Same assertions; not weakened.
- Step order: the cancellation sweep is step 2 (before the locks), plus a second sweep at the end only when step 4 abandoned a `createRound` this tick (the same-tick replacement T4 and C4 expect).
- `lockRound` keeps its signature and `LockOutcome`; after 3 stale attempts it throws (the tick logs `round_lock_failed`; the next tick retries). An overlapping close now answers `already_locked` where it answered `refused: no_house_question` (no caller or test depends on it).
- `readRoomDetail(env, roomId, user: {id, status}, t)` takes the session user (was the ID).
- `test/indexer/budget.test.ts`: a new test measures a dispatch with one Stakes final whose stats hook meets a 7-day backlog (day 1 held with 3 entrants, days 2–7 settled with 5,000 each); "a whole poll stays inside POLL_BUDGET" now adds that cost on top of the worst index and dispatch. Stricter, not weakened.
- `test/boards/boards.test.ts:95` asserted the old behaviour ("a refunded tie still has its tally"). The creators fixture had four refunded ties, so its values changed to keep the test's ranking and used-count tie-break with settled modes: u21 (0.5, 0.8, plus the refunded tie that no longer counts), u22 (2/3, 2/3, 8/9), u23 (0.8, 0.9, 0.25). The expected qualities are now 20/27, 0.65, 0.65 (were 7/9, 0.75, 0.75); the rows and ranks are the same. Counted, the tie would put u21 first.
- `test/stakes/prepare.test.ts` › "room rounds: members only…" and `prepare-review.test.ts` › R10 now turn `rooms.stakes.enabled` on before a member's ticket (the kill switch now applies there); their assertions are unchanged.
- L5 adds a tick step (step 6, `drainStakesStats`) beyond `stats/apply.ts`: without it a bounded hook call could leave a backlog that grows whenever a day has more Stakes entrants than one call covers (about 7,000).
- The room switch answers `stakes_disabled`, the code of the global kill switch, with its own message.
