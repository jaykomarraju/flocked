# W10-C handoff: Web Stakes entry + Claims

## Status

complete — a verified, eligible player can enter Stakes and claim from the browser against a mocked

minimum and R5 each have a passing, mutation-checked test.

## Summary

- **Stakes on Today** (`features/stakes`): `STAKES_UI_ENABLED` is on, and who sees Stakes is `/me`'s
  eligibility. `not_verified` is the one reason that still shows the mode, with the verify callout
  and "Verify with Coinbase"; every other reason hides it, toggle included (AC-8).
- **Verification**: the sheet carries the age attestation and the terms, then `POST /me/tos` and
  `POST /me/personhood`; in the mini app the authorize URL opens in an external browser
  (`MiniApp.openExternal`) and `/me` is polled until it lands.
- **The round config check**: every onchain `RoundConfig` field against the record published at lock,
  read through the client's own public RPC, plus `beaconRound` against the published `beaconDelay`.
  A mismatch — or a chain it cannot read — refuses to build `enter`, draws the refusal notice and
  disables the CTA; non-default values draw the round's special rules with their change-log IDs.
- **The entry**: encrypt with tlock, `/prepare`, then one sponsored user operation (`approve` then
  `enter`, `forceAtomic`) through the ERC-7677 paymaster proxy, pending until Base includes it.
- **The Stakes reveal**: it opens on the mode the player played and toggles; a Stakes result is
  provisional until the challenge window closes ("Provisional. Final at 11:03pm", "Payout, once
  final"), and a guardian veto redraws it as refunded.
- **Claims**: the list, claim-open times, "Claim all" in one batched user operation, wallet-only
  claims without an account.
- **A self-exclusion break** (Paper `core/global/self-excluded`): the question stays and everything
  there is to press goes. A break blocks entries in **both** modes, so the client no longer offers a
  Free entry the server would refuse.
- **W9-Z carry-over**: the toggle flipped, the counting minimum, review R5, the re-exported toggles.

## Spec issues

1. **The 30-day Stakes net has no API field.** "Compliance and responsible play" says the Stakes UI
   always shows it and Paper draws it in the header, but `/me` carries no such value (`GET
   /users/:handle` has only the lifetime net). The sheets draw Paper's example; the live header keeps
   the points balance, so live Stakes screens differ from Paper by that one slot. **Recommend**
   `stakes.net30d` (signed, USDC base units) on `MeResponse`, shown whenever Stakes is selected.
2. **"See the change log" has no destination** (Admin is W11-A). Built as a disclosure listing each
   non-default value with its audit ID. **Recommend** confirming, or linking it in W11.
3. **"Claim all" across merged accounts.** `claim`/`claimRefund` build their leaf from `msg.sender`,
   but `/claims` lists payouts of accounts merged into the caller, which may be other wallets. Built
   so the batch takes the connected wallet's and a line names the rest. **Recommend** the spec say
   this, or the escrow take a beneficiary.
4. **`GET /claims` carries no question or game day**, which the rows show, so the page reads `GET
   /rounds/:id` per listed round. **Recommend** adding `gameDay` and the prompt to `ClaimItem`.
5. **`enterWithPermit` is unreachable from a smart wallet** — USDC's EIP-2612 `permit` recovers an
   ECDSA signer. The client always sends `approve` then `enter`. **Recommend** the spec say the
   permit path is for EOA callers.
6. **Draft copy for approval**: `features/stakes/copy.ts` and `features/claims/copy.ts` in full.
7. **Confirm** that a refund shows at once rather than behind "Counting the flock…" (see Deviations).
